# Episode 03 - User Management & Role Based Access Control

## Overview

Pada episode ini fokus pengembangan diarahkan pada penyelesaian modul **User Management** serta implementasi **Role Based Access Control (RBAC)** untuk membatasi akses berdasarkan role pengguna.

---

# Backend

## User Management API

Berhasil menyelesaikan endpoint berikut:

### Self Service

* `GET /users/me`
* `PATCH /users/me`
* `PATCH /users/password`

Digunakan untuk kebutuhan pengguna yang sedang login.

### User Management

* `GET /users`
* `GET /users/:id`
* `POST /users`
* `PATCH /users/:id`
* `DELETE /users/:id`

Digunakan khusus untuk pengelolaan user oleh administrator.

---

## JWT Authentication

Payload JWT diperbarui agar menyimpan informasi role.

```json
{
  "id": "user-id",
  "role": "OWNER"
}
```

Dengan demikian backend dapat melakukan validasi hak akses berdasarkan role.

---

## Role Middleware

Menggunakan middleware yang sudah tersedia:

```ts
roleMiddleware(...)
```

Contoh penggunaan:

```ts
roleMiddleware('OWNER')
```

Middleware digunakan untuk melindungi endpoint manajemen user.

---

## Endpoint Protection

Endpoint berikut dibatasi hanya untuk role OWNER:

* GET `/users`
* GET `/users/:id`
* POST `/users`
* PATCH `/users/:id`
* DELETE `/users/:id`
* PATCH `/users/:id/reset-password`

---

## Reset Password User

Menambahkan endpoint:

```http
PATCH /users/:id/reset-password
```

Fitur ini memungkinkan administrator melakukan reset password user tanpa mengubah data profil lainnya.

# Security

## Hide Menu By Role

Menu User Management hanya ditampilkan untuk role:

```text
OWNER
```

Role lain tidak dapat melihat menu tersebut pada sidebar.

---

## Owner Route

Menambahkan route protection:

```text
/users
```

Jika role bukan OWNER maka pengguna akan diarahkan kembali ke dashboard.

---

## Backend Access Control

Walaupun route berhasil dibuka secara manual, backend tetap melakukan validasi role.

Hasil:

```text
OWNER
✓ Allowed

TEKNISI
✗ Forbidden
```
